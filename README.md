# Dangler Tune 🎸🩸

Гитарный тюнер для рок-группы Dangler. Базовый строй — **Drop B**, плюс Standard E, Drop D, D Standard, Eb, Drop C.
Металлический минимализм: гигантская нота во весь экран, портрет и ландшафт — кровь сама и есть прибор.

## Навигация: только свайпы

Никаких шестерёнок и шторок — три страницы в `HorizontalPager`:

| Свайп | Страница |
|---|---|
| ◀ | **СТРОЙ** — карточки строёв с мини-чипами струн, тап выбирает и возвращает в тюнер |
| ● | **ТЮНЕР** — нота на весь экран, кровь внутри неё и есть прибор |
| ▶ | **НАСТРОЙКИ** — темы, точность, эффекты, обновление |

На тюнере — нота на весь экран и точки страниц (тюнер на средней).
**Тап по экрану** — вылазят только 6 струн строя, ещё тап — прячут. Никаких дублей ноты, никакого «тишина».

## Звук: как устроено

Три слоя, у каждого одна причина для изменения (SRP):

- **`:core:dsp`** — только сигнал: `Decimator → FrameBuffer → SignalConditioner → FftMpmDetector → PitchTracker`.
  Ноль Android, ноль Compose, ноль понятий «струна/строй». Детектор можно заменить,
  не трогая тюнер.
- **`:core:tuner`** — только музыка: `TunerEngine` (режимы), `StringLocator` (залипание на струне),
  `NoteMath` (частоты ↔ ноты ↔ центы), строи. Тоже чистый Kotlin.
- **`:app`** — микрофон (`AudioRecorder`), Compose, самообновление.

- **McLeod Pitch Method** с NSDF через FFT (теорема Винера–Хинчина): `ACF = IFFT(|FFT(x)|²)`,
  стоимость O(N log N) вместо O(N²). Политика выбора пика одна и та же — `MpmSupport`
  (cutoff 0.97, проверка двойного периода), поэтому FFT-версия даёт ту же частоту, что прямая
  автокорреляция, но в 5–8 раз быстрее (0.6–0.9 мс против 4.4–4.8 мс на окно 2048, десктоп).
- **Второй проход для низких нот**: струна негармонична (`f_h ≈ h·f0·√(1+B·h²)`), и автокорреляция
  «уезжает» вверх на 3–6¢ на басу. После грубой оценки включается low-pass на `4·f0` — остаются
  первые гармоники, растяжение почти не влияет. На синтетическом B1 это дало p95 1.6¢ вместо 3.6¢
  и убрало +5.7¢ на атаке.
- Пайплайн: даунсемплинг ×2 (44100→22050, окно 2048 = 93мс — для B1 ~5.7 периодов, шаг 1024 =
  46мс) → удаление DC → low-pass ~1000Гц → RMS-gate 0.006 → MPM → clarity-gate 0.55
- Трекер: медиана-3, быстрая атака (скачок > 20¢ — сразу), релиз EMA 0.45,
  заморозка тихого хвоста (`holdFloor` 0.025, ±15¢) — игла не ползёт по шуму затухания
- Гитарный режим: `StringLocator` держит струну с гистерезисом (захват 1.5 полутона, удержание 2.5,
  перехват 1.0) — на границе соседних нот ничего не скачет
- **Метрики на синтетическом корпусе** (`PitchAccuracyTest`, `PitchCorpus`): 13 нот Drop B +
  Standard E + A4, негармоничность B=1e-4, затухание обертонов, шум 30 дБ →
  p95 ≤ 1.64¢, 0 октавных ошибок, 0 грубых ошибок; сквозной пайплайн p95 ≤ 1.85¢.
  При SNR 10 дБ p95 ≤ 2.9¢. Белый шум, розовый шум и постукивания — 0% ложных срабатываний.
  Позиция щипка 0.1–0.5 (провалы гармоник), обрезка низа микрофоном 90 Гц и резонанс корпуса
  200 Гц — p95 ≤ 2.0¢, 0 октавных ошибок. Это синтетика, не замена реальным WAV:
  комната, тело гитары и AGC телефона ещё не учтены.
- `LegacyEquivalenceTest` — golden-тест: после разбиения пайплайна числа обязаны совпадать со старой
  монолитной версией бит в бит (классический детектор подставляется явно).
  `FftEquivalenceTest` отдельно проверяет, что FFT-NSDF и прямая автокорреляция дают одну частоту
  (второй проход там выключен: он меняет результат осознанно).

## Проверка на реальных записях

Кидаешь WAV (mono/stereo, 16/24/32-bit PCM или float) в папку и гоняешь:

```bash
DANGLER_CORPUS_DIR=~/guitar-wavs ./gradlew :core:dsp:test --tests "*CorpusEvaluationTest"
```

Файлы называй по ноте: `B1.wav`, `E2_take2.wav`, `F#2.wav`. Отчёт печатает
частоту, джиттер p95 в центах, провалы, октавные скачки и отклонение от номинала.
Имя ноты нужно только для сравнения с номиналом; если не распозналось — метрики
стабильности всё равно считаются. Без переменной тест пропускается, CI не ломается.

## HERO: кровавая нота (`ui/components/BloodNote.kt`)

Стрелку-шкалу и строб выкинули — теперь сама нота и есть прибор:

- Стальной глиф (Black, ~66% высоты экрана) наполняется кровью **слева** (ниже строя) или **справа** (выше), уровень = `|cents| / 50`
- Глиф живой: squash на пружине от уровня крови (давит — плющится и раздаётся вширь), лёгкий wobble от фазы волны, упругий поп в точке
- Буквы вдавлены в металл (штамп): светлая кромка снизу-справа + тёмная сверху-слева
- Заливка строго внутри глифов: `saveLayer` + маска текста + `BlendMode.SrcIn`
- Центы сглажены (`animateFloatAsState` tween 120мс) + мёртвая зона ±2.5¢ на смену стороны — волна плывёт, а не дёргается
- В точке: заливка на 100% + кислотная вспышка + дыхание glow + вибрация
- По центру — едва видимая риска-датчик
## Хроматика: своя vs чужая (`ui/TunerViewModel.kt`)

Тюнер слышит **любую** ноту, а не только струны строя:

- Центы всегда хроматические — относительно ближайшей ноты 12-TET, осмысленны везде
- Нота из строя льётся **кровью**, чужая — **янтарём** (`chroma` в теме) — видно сразу
- В полоске струн (по тапу) активная струна повторяет логику: кровь / янтарь / кислота в точке
- Переключение нот быстрое: медиана по 3 кадрам, дебаунс тишины 120мс
- Задник — `MetalBackdrop`: движковая табличка (клёпаная рамка с болтами, царапины, масляные потёки) + шлифовка + виньетка

## Дизайн-система: Gloryhole-base, кровь Dangler

UI-кит (`ui/components/DanglerKit.kt`) портирован по механике из GloryholeVPN, палитра своя:

| Приём из Gloryhole | Как у нас |
|---|---|
| `AutumnGlassCard` (clip 24dp + glass + border 1dp, без теней) | `DanglerGlassCard`, бордер `blood 0x40FF2E2E` |
| `AutumnStatusPill` (дышащий бордер через `animateColorAsState`) | `DanglerStatusPill` (резерв) |
| `SettingsItemSwitch` (ряд 16dp + иконка + Switch) | `DanglerSwitchRow` |
| `DevTuningDialog`-слайдеры (акцентный thumb, моно-значения) | `DanglerSliderRow`, цифры — `Monospace` |
| Дыхание `tween + Reverse` (Blobatar / TactileConnectButton) | Дыхание glow ноты |

Темы (свои, не осенние): **Brutal Black**, **Blood Stage**, **Acid Rehearsal**. В точке всегда кислотный зелёный, расстройка — кровь.

## Обновление из приложения

Без Google Play: приложение проверяет GitHub Releases и ставит APK через FileProvider.
Настройки → **Обновление** → «Проверить». Если доступна новая версия, появляется
кнопка «Скачать и установить», а на тюнере — бейдж «ОБНОВА ↓».

- Проверка: `GET api.github.com/repos/badaiir/Dangler-Tune/releases/latest`, версии сравниваются численно (1.10 > 1.2)
- APK выбирается из ассетов по расширению `.apk` (а не `assets[0]`), качается в `cacheDir/updates` с прогрессом
- Проверка целостности: SHA-256 из GitHub asset digest + packageName, versionCode и подпись APK перед установкой
- Если запрещена установка из неизвестных источников — приложение ведёт в системные настройки, после возврата скачивание продолжается само
- Тихая проверка при старте и при открытии настроек (не чаще раза в минуту)
- Системное подтверждение установки пропустить нельзя — это ограничение Android для APK вне Google Play

Версия APK берётся из тега автоматически, вручную `versionName`/`versionCode` бампать не нужно:

```bash
git tag v1.13
git push origin v1.13   # → Release APK: CI подставит 1.13 (11300) и опубликует GitHub Release
```

Если текущее приложение было подписано другим ключом (например, старый локальный debug),
первая установка поверх не пройдёт: удали старую версию один раз. Дальше подпись совпадает.

## Сборка

Слабый ПК не мучаем — билдим через GitHub Actions:

```bash
git push origin main   # → Actions → Build APK → Artifacts: dangler-tune-apk
```

Локально: `./gradlew assembleDebug`. Установка: `adb install -r app-debug.apk`.
